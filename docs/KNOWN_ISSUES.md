# Known issues

Honest remaining limitations as of the final build. “Verified” means a test or command was
run in this environment; see `DEVLOG.md` for evidence.

| # | Issue | Severity | Status / mitigation |
| --- | --- | --- | --- |
| 1 | **No live AI provider test.** `GROQ_API_KEY` was not set. All discovery/ranking verification used a local OpenAI-compatible stub. | High for quality claims | Live tests are marked **NOT RUN**. The stub proves protocol, validation, progress, rate-limit and UI control flow only. Add a key in Settings and run a real analysis before judging clip quality. |
| 2 | **Windows was not built or tested on a clean VM.** Only Linux AppImage/`.deb`/unpacked app are verified. | High for Windows release | `electron-builder` Windows config exists and the code avoids Linux-only paths where practical, but this is unverified. Build and run acceptance on a clean Windows VM before shipping. |

| 4 | **Hardware encoding is not available on the build machine.** All four encoder test encodes failed; the app recommends `low profile` and software `libx264`. | Medium | Test-encode gate prevents claiming NVENC/QSV/AMF/VAAPI when unusable. Expect software encoding on similar laptops. |
| 5 | **Face tracking / active speaker framing is not implemented.** Studio uses fill, blur-fill or manual center crop with static zoom. YuNet is pinned but unused. | Medium | The UI says “Face tracking is not enabled in this build.” Do not market auto-reframing. |

## Not issues, but easy to misread

- **“Engine ready”** means the process handshake succeeded, not that a provider key exists.
- **“Connection ok”** in Settings tests the provider endpoint/capabilities; it does not run a
  full analysis.
- **“succeeded”** for a render means ffprobe + full decode + output validation passed; it does
  not mean the creative content is good.
- **Screenshots** use real fixture media, a real local transcript and a real render. The
  showcase candidate titles/rationales were authored for the demo, as documented.
